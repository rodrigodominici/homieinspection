# Architecture rules
- Rent Manager report links use a canonical public app origin, a role-protected inspection entry for internal reports and the captured owner token for public reports; production photo URLs must be HTTPS and non-local. Why: dispatcher hosts and audience fallbacks must not produce wrong or unsafe links.
- Rent Manager events use transactional CL captacion triggers and atomic ordered claims; draft simulation has a separate delivery ledger and never marks real events sent. Hosted retries use a one-minute SQL wake job armed on enqueue or retry and unscheduled on drain; wakes use single-use credentials and an empty outbound URL never claims events. Why: retries must preserve order without idle polling or confusing simulation with real delivery.
- Rent Manager final-photo delivery reads the complete current after-stage gallery ordered by sort_order, created_at and id, including empty lists, before signing data.fotos. Why: each notification replaces the receiver's entire gallery and queued snapshots may be obsolete.
- Rent Manager visit availability uses typed inspection fields, authenticated transactional RPCs and offline RPC replay; rescheduling transfers the active property reference, preserves old evidence and resets the new visit's answers. Why: retries and interrupted visits must not duplicate replacements or leak assignments.
- Anonymous marketing downloads use property-scoped HMAC expiry tokens in URL fragments, validated server-side before issuing short-lived exact-object URLs; no anonymous table/bucket grants. Why: Slack recipients can download without accounts without exposing other inspection evidence.
- Hunter access is a protected user_roles grant, with approved/active checks in read-only captacion RPCs and exact marketing-object Storage policies for CL/MX; legacy profile roles remain unchanged and Hunter profiles use a nonprivileged placeholder. Why: global photo access must not grant inspection editing or other roles' data.
- Marketing photo Slack notices use a dedicated configurable channel with shared-channel fallback after completed section and persisted minimum-photo checks, with authenticated triggers including offline replay and a delivery claim ledger. Why: routing photo notices must not change other alerts or announce incomplete or duplicate galleries.
- PA marketing galleries resolve captacion photos through an assigned check-in with identical property_id and market; protected read-only RPC and exact-object Storage authorization preserve existing receiver assignments and private media. Why: PA access must not expose other properties or grant captacion editing rights.
- Quotation revisions with an existing OT use a separate draft/change ledger and transactional investor decisions; approved changes update the same OT, affected items pause during review, and removals archive rather than erase evidence. Why: edits must not bypass approval or rewrite completed work.
- Sent quotation history reuses immutable inspection_report_versions snapshots; admin and executive publication use publish_quotation_version transactionally, while comparison and PDF read only captured pricing/tax/discount and per-version owner decisions. Why: republication must not rewrite evidence or race version allocation; destructive inspection deletion remains the explicit admin exception.
- Pending quotation items use an explicit is_pending_quote flag across pricing, published snapshots, owner decisions and work-order eligibility; zero price alone never means pending. Why: unpaid estimates must not be confused with free approved work.
- Rent Manager listing lookup maps location.unit to unit_number without parsing street addresses. Why: the upstream response includes apartments separately from the address.
- Chilean HubSpot captación intake recovers missing unit_number from the verified deal property numero_de_departamento before saving the normalized snapshot, while retaining the raw webhook. Why: incoming deal events omit the apartment even when HubSpot has it.

- Offline app shell uses `vite-plugin-pwa` (generateSW → `/sw.js`, NetworkFirst for HTML and REST GETs) registered only from `src/lib/register-sw.ts`, which refuses dev/preview/iframe/`?sw=off`. Why: the old unguarded worker trapped installed devices on stale builds.
- Opening an inspection online must save its snapshot and preload every inspector screen (`src/lib/offline-readiness.ts`) before showing "Lista para usar sin conexión"; `/assets/` also has a CacheFirst runtime cache. Why: screen files never fetched online made offline navigation hang on iPhone.
- Inspector writes (field values, section status, photos) go through `src/shared/lib/offline-queue.ts` (IndexedDB outbox replayed on reconnect); submitting is blocked while the outbox is non-empty. Why: receptors in México work without signal.
- Inspection address/property_name always include the unit (", D <unit>") via DB trigger apply_unit_to_inspection_address, skipping if already present. Why: receptors must see the apartment on every screen without per-screen changes.
- Captación marketing photos live in section_key marketing_photos (min 10, enforced in section-completion.ts); DB trigger tag_marketing_photo sets photo_stage='marketing' and hides them from owner reports. Why: a separate app will consume them for portal listings.
- Test inspections use inspections.is_test (set only from optional es_prueba on rent_manager intake); Slack, email and HubSpot functions skip them, Rent Manager events still flow, admin metrics/lists exclude them, and admin-only admin-purge-inspections deletes rows atomically via purge_inspections before removing Storage files. Why: production testing must not notify people or pollute metrics and must leave no residue.
